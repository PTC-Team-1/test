# 🐰 CodeRabbit（コードラビット）使い方ガイド

**CodeRabbit** は、あなたが書いたコードをAIが自動でチェックして、改善点やバグを優しく教えてくれる **「AIコードレビューアシスタント」** です✨

先輩エンジニアにコードを見てもらう前の **「セルフレビュー（下書きチェック）」** や、24時間いつでも質問できる **「プログラミング学習の先生」** としてどんどん活用しましょう！

> [!TIP]
> **ツールの初期設定は一切不要です！**
> すでにこのリポジトリに導入されているため、普段通りにGitHubでプルリクエストを作るだけで自動的に動きます。

---

## 🛠️ 0. 準備：ブランチ作成〜プルリクエスト（PR）作成まで

CodeRabbitにレビューしてもらうためには、まず自分の作業用ブランチを作り、GitHub上でプルリクエスト（PR）を作成する必要があります。

### ① 作業用のブランチを作る（ターミナル操作）
`main` ブランチに直接書き込むのではなく、必ず新しいブランチを作ってから作業を始めましょう。

```bash
# 1. 最新のmainブランチに移動して最新化する
git checkout main
git pull origin main

# 2. 新しい作業用ブランチを作成して移動する（ブランチ名は自由です）
git switch -c feature/add-login
```

### ② コードを書いてGitHubへプッシュする（ターミナル操作）
コードを書いたり修正したりしたら、変更を記録してGitHubに送信（プッシュ）します。

```bash
# 1. 変更したファイルをステージング（記録の準備）する
git add .

# 2. 変更内容のメモをつけて保存（コミット）する
git commit -m "ログイン画面のレイアウトを作成"

# 3. GitHubに自分のブランチを送信（プッシュ）する
git push origin feature/add-login
```

### ③ GitHub上でプルリクエスト（PR）を作成する（ブラウザ操作）
プッシュが終わったら、ブラウザでGitHubのリポジトリページを開きます。

1. 画面上部に表示される緑色の **`Compare & pull request`** ボタンをクリックします。
   （※表示されない場合は、「Pull requests」タブ ＞ 「New pull request」から自分のブランチを選択します）
2. **タイトル** と **説明文**（どんな変更をしたか）を入力します。
3. 右下の緑色の **`Create pull request`** ボタンを押せば完了です！

> [!IMPORTANT]
> **「Draft（下書き）」で作ることもできます！**
> `Create pull request` ボタンの右端にある `▼` を押して **`Create draft pull request`** を選ぶと、「まだ作業途中です」という状態でPRを作れます。

## 🚀 1. CodeRabbitを使ったレビューの流れ

プルリクエストを作成すると、いよいよCodeRabbitの出番です！

### ⏳ ステップ1：少し待つ（1〜3分ほど）
PRを作ると、CodeRabbitが自動でコードを読み込み始めます。PRの画面に **ウサギのアイコン（🐰）** のコメントが投稿されるまで少し待ちましょう。
※すでに作成済みのPRに新しく `git push` した場合も自動で反応します。

### 📝 ステップ2：変更のまとめ（サマリー）を読む
最初に、CodeRabbitから **「今回のPRで何を変更したのか」の要約コメント** が届きます。
自分が意図した通りの変更になっているか確認しましょう。

### 🔍 ステップ3：コードへのアドバイスを確認する
「Files changed（変更されたファイル）」タブやコメント欄を見ると、コードの特定の行に対してアドバイスが付いています。
* 🐛 **バグの指摘**：「この書き方だとエラーになる可能性があります」
* ✨ **改善案**：「こう書くとよりスッキリして読みやすくなります」
* 🔒 **セキュリティの注意**：「パスワードなどの機密情報がそのまま書かれています」

### 🛠️ ステップ4：コードを直す
指摘を見て納得したら、手元のエディタでコードを修正して再度 `git add` → `git commit` → `git push` します。

> [!NOTE]
> **ワンクリックで修正できることも！**
> CodeRabbitのコメント内に **`Commit suggestion`（提案を反映）** というボタンが出ている場合は、そのボタンを押すだけでGitHub上で直接コードを修正することもできます。

## 💬 2. AIに質問・お願いをする方法（チャット機能）

CodeRabbitは、ただ指摘するだけでなく **チャットで会話（質問）** ができます。わからないことがあれば、恥ずかしがらずにどんどん聞いてみましょう！

### 🙋 指摘の内容がよくわからないとき
CodeRabbitのコメントの下にある **「Reply（返信）」** 欄に、そのまま日本語で質問を書きます。

```text
💬 質問の例：
「なぜこの書き方だとエラーになるのですか？初心者向けにわかりやすく教えてください。」
「この修正案のコードがどういう動きをしているか、1行ずつ解説してください。」
```

### ⚡ 便利な指示コマンド一覧
PRのコメント欄に `@coderabbitai` をつけて以下の言葉を送ると、特別な作業をしてくれます。

| 入力するコマンド | やってくれること | こんな時に使う |
| :--- | :--- | :--- |
| `@coderabbitai review` | 🔄 もう一度レビューしてもらう | コードを直してプッシュしたのに反応がない時 |
| `@coderabbitai summary` | 📋 変更のまとめを更新する | たくさん修正して、最初の要約と内容が変わった時 |
| `@coderabbitai generate docstrings` | 📝 コードの説明コメントを書く | 関数やメソッドに「何をする処理か」のメモを自動で作ってほしい時 |
| `@coderabbitai generate unit tests` | 🧪 テストコードを作る | 自分のコードが正しく動くか確かめるための「テストコード」の例を書いてほしい時 |
| `@coderabbitai pause` | ⏸️ 自動レビューを一時停止する | まだ作業途中で、完成するまでレビューを待ってほしい時 |
| `@coderabbitai resume` | ▶️ 自動レビューを再開する | 一時停止していたレビューを再び動かしたい時 |

## 💡 3. 学習中におすすめの活用コツ

<details>
<summary><b>🐣 コツ①：まずは「Draft（ドラフト）PR」で作ってみる</b></summary>
<br>
「まだ完成していないけど、とりあえずAIにチェックしてほしい！」という時は、PR作成時に <b>Draft pull request</b> として作成するのがおすすめです。<br>
（※リポジトリの設定によってはDraftでは自動起動しない場合があるため、動かなければコメント欄で <code>@coderabbitai review</code> と打ってみてください！）
</details>

<details>
<summary><b>🤖 コツ②：AIの指摘を「鵜呑み」にしすぎない</b></summary>
<br>
CodeRabbitはとても優秀ですが、たまに「今の機能には不要な高度な書き方」を提案してくることもあります。<br>
「なるほど、そういう書き方もあるんだな」と学びつつ、採用するかどうかは自分で考えてみましょう！迷ったら「これは今すぐ直すべきですか？」とAI自身に聞いてみるのもアリです。
</details>

<details>
<summary><b>🎉 コツ③：褒められたら素直に喜ぶ！</b></summary>
<br>
良いコードを書くと、CodeRabbitが「素晴らしい実装です！」「とても読みやすいコードですね」と褒めてくれることがあります。モチベーションアップに繋げましょう！
</details>
